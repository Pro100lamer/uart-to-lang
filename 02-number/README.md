# 02. Складываем числа и выводим результат числом

Вторая статья серии. Здесь две вещи.

**Работа над ошибками.** Вывод в UART теперь правильный: перед каждым
байтом ждём освобождения передатчика, а линию сначала настраиваем. В
первой статье этого не было, и на настоящем железе тот код развалился
бы. Подробности в `../01-hello-fixed/`.

**Обещанное число.** Считаем `2 + 2`, печатаем результат числом. Затем
`20000 + 2345`, чтобы задача не сводилась к одной цифре.

## Что тут неожиданного

Напечатать `4` просто: прибавить к четвёрке код символа `'0'`, то есть
48, и получить 52, что и есть символ `4`.

Напечатать `22345` уже нельзя без деления на десять: цифры достаются с
конца, а последняя цифра это остаток от деления. И вот тут выясняется,
что **в базовом наборе RV32I команды деления нет вообще**. Как и
умножения. Они живут в расширении M, которое мы не подключали.

Поэтому `div10` делит вычитанием: сколько раз десятка помещается в
число, столько и частное. Медленно и наглядно.

## Ещё две новые вещи

**Появилась секция `.bss`.** Строку из числа надо где-то собирать, а до
сих пор мы только читали из памяти. Шестнадцать байт буфера в ОЗУ,
линкер-скрипт про них знает.

**Появились подпрограммы, но без стека.** Возврат идёт не через `ra`, а
через явно выбранные регистры: `putc` возвращается по `t6`, `print_str`
по `t4`, `print_dec` по `t5`, `div10` по `t3`. Так сделано потому, что
стека у нас пока нет, и сохранять адрес возврата при вложенном вызове
негде. Стек будет в третьей статье.

## Предупреждение линкера

Сборка выдаёт:

```
warning: hello.elf has a LOAD segment with RWX permissions
```

Это правда: код и данные лежат в одном сегменте, который одновременно
пишется и исполняется. На настоящей системе так не делают. Чиним в
статье про ELF и линкер, где будет чем чинить.

## Сборка и запуск

```
make
make run
```

Ожидаемый вывод:

```
2 + 2 = 4
20000 + 2345 = 22345
```

С пропатченным QEMU, который выдерживает настоящую скорость линии
(см. `../../qemu-uart-pacing/` в публичном репозитории):

```
qemu-system-riscv32 -global serial-mm.xmit-pacing-baud=115200 \
    -machine virt -nographic -bios none -kernel hello.elf
```

Вывод тот же, все 31 байт на месте. Если убрать ожидание THRE из
`putc`, на 115200 бодах останется один байт.
