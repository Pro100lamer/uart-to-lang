## Главное: кто вообще читает точку входа

Статья утверждает, что на стенде поле «точка входа» декоративно, и это верно
для запуска через `-kernel`. Первый же комментарий указал, что QEMU умеет и
иначе. Умеет. Вот все четыре способа на одном файле, `make loader`:

| запуск | на экране | чему следовал |
|---|---|---|
| `-bios none -kernel decoy.elf` | `X` | адресу из ПЗУ машины |
| `-bios none -device loader,file=decoy.elf` | `X` | тому же |
| `-bios none -device loader,file=decoy.elf,cpu-num=0` | числа | точке входа |
| `-bios decoy.elf` | числа | точке входа |

Ловушка печатает `X` по `0x80000000`, точка входа в заголовке указывает на
`0x8000001c`. Дело не в самом `-device loader`, а в его параметре `cpu-num`:
без него загрузчик раскладывает байты по заголовкам, но счётчик команд не
трогает.

## Но интереснее другое: что именно меняется

`make resetvec` снимает слово по `0x1018`, то самое, которое переходник
машины читает перед прыжком:

```
-bios none -kernel hello.elf    0x80000000
-bios none -kernel high.elf     0x80000000
-bios hello.elf                 0x80000000
-bios high.elf                  0x80100000
```

`hello.elf` собран по `0x80000000`, `high.elf` по `0x80100000`.

**Под `-kernel` переходник машины не зависит от файла вообще.** Какой файл ни
подсунь, управление уйдёт по адресу, зашитому в машину. А `-bios high.elf`
этот переходник переписал, взяв адрес из заголовка.

Вот и вся разница. `-bios` и `-device loader,cpu-num=0` это удобства
эмулятора: они дают файлу распорядиться тем, откуда машина стартует. На
настоящем кристалле адрес сброса зашит в железо. Поэтому стенд всей серии и
стоит на `-bios none`: нужна машина, которая ведёт себя как железо, а не как
эмулятор с удобствами.

## Третья форма loader

`make force`. Оказалось, `-device loader,addr=<адрес>,cpu-num=0` БЕЗ `file`
принудительно задаёт reset-vector:

```
-device loader,file=decoy.elf                                  X
  + -device loader,addr=0x8000001c,cpu-num=0                   числа
  + -device loader,addr=0x80000000,cpu-num=0                   X
```

Подсказал maquefel, проверено.

## Перечень читающих, собранный за два дня треда

**Читают точку входа:** `-device loader,cpu-num=0`, `-bios`, `bootelf` в
U-Boot, `load` в gdb, ядро Linux, `qemu-user`.

**Не читают:** `-kernel`, `-device loader` без `cpu-num`, `load_image` в
OpenOCD. А в образе после `objcopy -O binary` читать уже нечего: заголовков
там физически нет.

Про `-kernel` стоит сказать точнее, чем сказано в статье. Он не просто не
читает, он и НЕ ДОЛЖЕН: это опция для загрузки U-Boot Proper или ядра Linux
после отработки встроенного OpenSBI, и они стартуют уже в S-MODE.

## Две грабли, обе выстраданы

**`-bios none` обязателен** в первых трёх строках таблицы. Без него QEMU
подставляет свой OpenSBI, и на экране оказывается его загрузочный баннер, а
не наш вывод. Я один раз так снял таблицу, где все четыре строки выглядели
одинаково и бессмысленно.

**Программы не завершаются**, поэтому в целях каждый запуск обёрнут в
`timeout 3`. Без этого `make loader` висит до `Ctrl-A X`, и так четыре раза
подряд.
