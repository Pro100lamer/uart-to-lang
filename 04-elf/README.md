# 04. ELF и компоновщик

Стенд четвёртой статьи. Программа взята из третьей и не менялась ни на
инструкцию: меняется только то, как её раскладывают по файлу.

Итоговый скрипт компоновщика это `link-entry.ld`: в нём собрано всё, что
разбирается в статье. Остальные `link-*.ld` это промежуточные шаги, по одному
на каждую находку, они оставлены нарочно, чтобы было видно, что менялось.

## Что показывают файлы

| Файл | Что в нём |
|---|---|
| `boot.s` | программа из третьей статьи, без изменений |
| `link.ld` | скрипт из третьей статьи: один сегмент на всё, отсюда RWX |
| `link-phdrs.ld` | сегменты объявлены блоком `PHDRS`, права раздельные |
| `link-assert.ld` | то же плюс `ASSERT`, компоновщик сам сверяет размер стека |
| `link-assert-small.ld` | стек 128 байт при пороге 736: сборка обязана упасть |
| `link-high.ld` | программа по `0x80100000` |
| `link-entry.ld` | **итоговый:** PHDRS плюс `.text.entry` плюс `ASSERT`, всё сразу |
| `boot-decoy.s` | ловушка в `.text` перед `_start` |
| `boot-entry.s` | та же ловушка, но `_start` вынесен в `.text.entry` |
| `dump-mem.py` | дамп памяти работающей машины через монитор QEMU |
| `break-entry.py` | портит в готовом ELF одно поле, точку входа |

## Опыты и что каждый доказывает

```
source ../../scripts/env.sh
make            # три сборки: hello с предупреждением, phdrs и assert без
make run        # обычный прогон
```

**Точка входа не читается.** `make decoy` печатает `X` вместо чисел.
Компоновщик кладёт ловушку по `0x80000000`, `_start` уезжает на
`0x8000001c`, и точка входа в заголовке честно становится `0x8000001c`.
Управление всё равно уходит на `0x80000000`.

**Адрес загрузки тоже не читается.** `make high` не печатает ничего:
программа лежит по `0x80100000`, управление туда не приходит.

**Поля для машины не существует.** `make broken-entry` правит в готовом ELF
ровно 4 байта заголовка, ставя точку входа `0xdeadbeef`. Программа не
пересобирается, байты кода не двигаются. Считает как ни в чём не бывало.
Это самый прямой из четырёх опытов: в остальных поле менялось вместе с
программой, а здесь только оно.

**Порядок в файле лечится секцией.** `make entry` считает числа верно, хотя
ловушка в исходнике по-прежнему стоит раньше. `_start` встаёт на
`0x80000000`, ловушка уезжает на `0x800001a0`.

**Компоновщик умеет проверять.** `make small` обязана упасть:

```
ld.exe: stack too small for fib(46)
collect2.exe: error: ld returned 1 exit status
```

**Откуда берётся адрес.** `make resetvec` снимает дамп по `0x1000` у
работающей машины. Там 6 инструкций, которые читают слово по `0x1018` и
прыгают по нему. В слове лежит `0x80000000`.

## Заглянуть внутрь

```
make elf        # readelf -h, -S и -l на assert.elf
```

Числа, на которые опирается статья: в файле 444 байта, в памяти 1488,
разница 1044 это `.bss` (16) и `.stack` (1028).
