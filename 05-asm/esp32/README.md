# Первая программа серии на живом ESP32

Серия идёт на RISC-V, а ESP32 на Xtensa, так что наши образы сюда не
встанут. Стенд нужен для другого: показать на кристалле то же самое,
что мы разбирали на бумаге. Строка `movi a3, message` не исполняется,
её исполняет `l32r`, а адрес в слово данных вписывает компоновщик.

Плата: ESP32-D0WD rev 1.1, переходник CH340, порт COM4 по умолчанию.

## Что нужно

* тулчейн Xtensa из релизов [espressif/crosstool-NG](https://github.com/espressif/crosstool-NG/releases),
  архив `xtensa-esp-elf-*-x86_64-w64-mingw32.zip`, распакованный в
  `tools/xtensa-esp-elf`;
* `pip install esptool` (тянет за собой pyserial).

## Команды

    make backup     снять образ флеша ЦЕЛИКОМ, делать ПЕРВЫМ
    make listing    что написано и что кристалл исполняет
    make run        прошить и запустить, плата печатает Привет с железа!
    make nowait     то же без ожидания передатчика, вывод рвётся
    make iram-byte  чтение байта из памяти команд, кристалл падает
    make restore    вернуть плату к тому, что на ней было

Порт задаётся так: `ESP_PORT=COM7 make run`.

**Цели `run`, `nowait` и `iram-byte` пишут во флеш по адресу `0x1000`,
поверх загрузчика платы.** Сначала `make backup`. У нас на плате лежала
чужая прошивка от ABUP, и она к тому моменту всё равно не запускалась:
`image at 0x20000 has invalid magic byte`, петля перезагрузки.

Снятые ответы платы лежат в `вывод-платы.md`.

## Три ловушки, каждая стоила прогона

**Режим флеша обязан быть `dio`.** По умолчанию `esptool elf2image`
ставит `qio`. ПЗУ читает заголовок и первый сегмент нормально, а на
втором отдаёт мусор:

    mode:QIO, clock div:2
    load:0x3ffb0000,len:20
    load:0x62166542,len:55056229

Второй адрес я нашёл поиском по снятому образу флеша: он лежит по
смещению `0xCDD00`, в чужой прошивке. То есть ПЗУ не прочло заголовок,
а показало то, что осталось в буфере от предыдущего чтения. В старом
журнале загрузки платы стояло `mode:DIO`, оттуда и разгадка.

**У регистров UART два адреса.** Настройки читаются по `0x3FF40000`, а
буфер передачи доступен только через псевдоним `0x60000000`. По первому
адресу запись просто не доходит.

**Ждать передатчик обязательно.** Кристалл на 240 МГц кладёт байты в
буфер быстрее, чем провод на 115200 их отдаёт. Без ожидания из
`Привет с железа!` выходит нечитаемая рвань. В QEMU этой беды нет: модель
принимает байт мгновенно, поэтому первая программа серии обходится
без проверки и работает.

**Побайтовое чтение памяти команд запрещено.** `l8ui` по адресу в IRAM
роняет процессор, и он сам говорит, чем недоволен:

    Fatal exception (3): LoadStoreError
    epc1=0x40080412, excvaddr=0x40080420

`excvaddr` указывает ровно на строку. Поэтому строка лежит в памяти
данных, а `.literal` в памяти команд: `l32r` читает слово данных
32-битным доступом, и это законно.
