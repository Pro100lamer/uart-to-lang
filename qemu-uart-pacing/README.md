# Патч к QEMU: UART, который ведёт себя как железо

Патч для модели NS16550A в QEMU. Заставляет эмулируемый передатчик
выдерживать темп линии, чтобы код, забывший опрашивать бит THRE, терял
данные ровно так, как потерял бы на настоящей плате.

Появился из комментария к [первой статье серии](https://habr.com/ru/articles/1065554/):
читатель заметил, что перед записью каждого байта надо дожидаться
освобождения передатчика. Он прав, а проверить это внутри эмулятора
было нечем.

## В чём проблема

В стоковой модели запись байта в регистр передатчика сбрасывает бит
THRE, но тут же, в том же обработчике, синхронно вызывается
`serial_xmit()`, который возвращает бит обратно. Гость не может застать
передатчик занятым: THRE снят ноль тактов.

Отдельного таймера передачи в модели нет. Переменная
`char_transmit_time` считается из делителя скорости и формата кадра, но
расходуется на таймаут FIFO и опрос модемного статуса, а не на темп
отправки.

Проверить это можно программой `probe.s` из этого каталога: она пишет
байт и следующей же инструкцией читает LSR. На стоковом QEMU вывод
всегда `X1X1X1...`, где `1` означает «передатчик свободен».

Проблеме много лет. Багрепорт
[#1086745 «serial port data THRE comes too early»](https://bugs.launchpad.net/qemu/+bug/1086745)
описывает её же с другой стороны и предлагает то же решение, таймер по
`char_transmit_time`. Статус Expired с марта 2018 года.

## Что делает патч

Добавляет таймер, который держит THRE снятым в течение времени
передачи символа. Запись в занятый регистр больше не запускает
отправку: байт затирает предыдущий и пропадает, как на железе.

Поведение по умолчанию не меняется. Всё включается свойствами
устройства.

| Свойство | Значение |
|---|---|
| `xmit-pacing` | `on` включает пейсинг по делителю, который задал сам гость |
| `xmit-pacing-baud` | скорость в бодах; включает пейсинг и переопределяет делитель гостя |

Второе свойство удобно для программ, которые линию вообще не
настраивают: скорость задаётся снаружи, программа не меняется.

Пейсинг работает только в нефифошном режиме. FIFO намеренно не тронут:
у него своя логика вытеснения, и мешать две вещи в одном патче не
стоит.

## Сборка

Патч против QEMU 9.2.4.

```bash
curl -LO https://download.qemu.org/qemu-9.2.4.tar.xz
tar xf qemu-9.2.4.tar.xz
cd qemu-9.2.4
patch -p1 < ../uart-pacing.patch
mkdir build && cd build
../configure --target-list=riscv32-softmmu --disable-werror --disable-docs \
             --disable-guest-agent --disable-tools --disable-slirp \
             --disable-vnc --disable-gtk --disable-sdl --disable-curses \
             --disable-libssh --disable-tpm --disable-spice --disable-opengl \
             --audio-drv-list=
ninja qemu-system-riscv32
```

Под Windows собирается в MSYS2 MINGW64. Нужны пакеты `gcc`, `glib2`,
`pixman`, `python`, `ninja`, `meson`, `pkgconf`, `dtc`, плюс `diffutils`
и `git` из msys. Сборка одной цели заняла около двенадцати минут.

## Как пользоваться

```bash
# прежнее поведение, ничего не изменилось
qemu-system-riscv32 -machine virt -nographic -bios none -kernel hello.elf

# линия на 115200 бод, как на большинстве плат
qemu-system-riscv32 -global serial-mm.xmit-pacing-baud=115200 \
    -machine virt -nographic -bios none -kernel hello.elf
```

## Что получается

Строка 231 байт, программы собираются генератором `gen.py`.

| Вариант программы | Без флага | 115200 бод |
|---|---|---|
| Пишет в THR без опроса | 231 из 231 | **1 из 231** |
| Ждёт THRE перед каждым байтом | 231 из 231 | 231 из 231 |

Время передачи опрашивающего варианта совпадает с расчётным
`байт × 10 / скорость` с точностью до постоянных накладных расходов
порядка 390 мс на старт эмулятора:

| Скорость | Замер | Расчёт |
|---|---|---|
| 300 | 8082 мс | 7700 мс |
| 1200 | 2282 мс | 1925 мс |
| 9600 | 656 мс | 240 мс |
| 115200 | 412 мс | 20 мс |

## Оговорки

Патч не отправлен в апстрим QEMU. Проект принимает вклад только письмом
в рассылку `qemu-devel@nongnu.org`, и для отправки патч нужно переложить
на master, перевести комментарии на английский и подписать реальным
именем.

Проверялось на QEMU 9.2.4, машина `virt`, архитектура RISC-V 32,
нефифошный режим, Windows. Другие машины и модели UART не проверялись.
