# 01. «Привет, мир» в UART

Первая программа серии: цикл из пяти инструкций пишет строку байт за байтом
в регистр UART эмулируемой машины RISC-V. Ни ОС, ни загрузчика, ни
стандартной библиотеки.

В этом каталоге лежат только исходники — четыре файла. Инструментов здесь
нет: тулчейн весит около полутора гигабайт, в репозитории ему не место.
Поэтому просто клонировать и набрать `make` не получится, сначала надо
поставить инструменты. Это один раз и без установщиков.

## Шаг 1. Ставим инструменты

Три zip-архива, всё распаковкой. Права администратора не нужны, в систему
ничего не прописывается.

| Что | Версия |
|---|---|
| xPack QEMU RISC-V | 9.2.4-1 |
| xPack RISC-V GCC | 15.2.0-1 |
| xPack Windows Build Tools | 4.4.1-3 |

Ниже команды для Windows. Под Linux и macOS у тех же проектов на GitHub
лежат свои архивы — меняются только имена файлов.

```bash
mkdir tools && cd tools

curl -L -o qemu.zip https://github.com/xpack-dev-tools/qemu-riscv-xpack/releases/download/v9.2.4-1/xpack-qemu-riscv-9.2.4-1-win32-x64.zip
unzip -q qemu.zip && mv xpack-qemu-riscv-9.2.4-1 qemu && rm qemu.zip

curl -L -o gcc.zip https://github.com/xpack-dev-tools/riscv-none-elf-gcc-xpack/releases/download/v15.2.0-1/xpack-riscv-none-elf-gcc-15.2.0-1-win32-x64.zip
unzip -q gcc.zip && mv xpack-riscv-none-elf-gcc-15.2.0-1 riscv-gcc && rm gcc.zip

curl -L -o bt.zip https://github.com/xpack-dev-tools/windows-build-tools-xpack/releases/download/v4.4.1-3/xpack-windows-build-tools-4.4.1-3-win32-x64.zip
unzip -q bt.zip && mv xpack-windows-build-tools-4.4.1-3 build-tools && rm bt.zip
```

Если под рукой нет `curl` и `unzip` — скачайте те же три архива браузером
с релизных страниц GitHub и распакуйте в `tools\`, переименовав каталоги
в `qemu`, `riscv-gcc` и `build-tools`.

## Шаг 2. Показываем инструменты терминалу

Это тот шаг, который пропускают чаще всего. Без него `make` отвечает
«команда не найдена» — и дело не в проекте, а в том, что терминал не знает,
где лежат инструменты.

Настройка живёт только в текущем окне терминала. Закрыли окно — надо
повторить. В систему намеренно ничего не прописывается.

**Git Bash:**

```bash
export PATH="/d/путь/к/tools/riscv-gcc/bin:/d/путь/к/tools/qemu/bin:/d/путь/к/tools/build-tools/bin:$PATH"
```

**PowerShell:**

```powershell
$env:PATH = "D:\путь\к\tools\riscv-gcc\bin;D:\путь\к\tools\qemu\bin;D:\путь\к\tools\build-tools\bin;" + $env:PATH
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
```

Вторая строка в PowerShell обязательна. Консоль по умолчанию работает не в
UTF-8, и «Привет, мир!» приедет кракозябрами — при полностью исправной
программе.

**Проверяем, что получилось:**

```
riscv-none-elf-gcc --version
qemu-system-riscv32 --version
make --version
```

Все три должны ответить. Если хоть одна команда не найдена — дальше идти
бессмысленно, вернитесь к этому шагу.

## Шаг 3. Собираем и запускаем

Из этого каталога:

```
make
make run
```

Ожидаемый вывод:

```
Привет, мир!
```

Программа не завершается сама — она уходит в бесконечный цикл, и QEMU
висит. Выход: `Ctrl-A`, отпустить, затем `X`. Убрать собранный ELF:
`make clean`.

## Если не работает

- **`make: команда не найдена`** — пропущен шаг 2, либо окно терминала
  новое. Настройка `PATH` действует только в том окне, где её выполнили.
- **`make: *** No rule to make target`** — вы не в том каталоге. Команды
  выполняются из каталога с `Makefile`.
- **`missing separator`** — в `Makefile` испортились отступы. В рецептах
  должна быть табуляция, а не пробелы; часто ломается при копировании
  через веб-интерфейс. Клонируйте репозиторий, а не копируйте файл.
- **Вместо букв кракозябры** — терминал не в UTF-8. Программа тут ни при
  чём: она отдаёт байты, а собирает их обратно в буквы терминал.

## Что здесь лежит

- `link.ld` — карта памяти. Почему `0x80000000`: у машины `virt` ОЗУ
  начинается с этого адреса, туда QEMU и передаёт управление при `-bios none`.
- `boot.s` — программа. Цикл записи байтов строки по адресу `0x10000000` —
  это регистр данных UART 16550.
- `Makefile` — сборка, запуск, уборка.

Программа не завершается: под bare metal возвращаться некуда, поэтому
в конце `wfi` в бесконечном цикле.

Строка «Привет, мир!» — двенадцать символов, но двадцать один байт:
девять кириллических букв весят в UTF-8 по два байта, а запятая, пробел
и восклицательный знак — по одному. С переводом строки в UART уходит
двадцать два байта. Цикл в `boot.s` про символы ничего не знает, он
толкает байты по одному.
